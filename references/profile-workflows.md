# Exact Profile workflows

Exact Profile 保存跨项目复用、需要逐字保真的个人事实。它属于统一 Memory Home 的
Personal Memory 子层，默认位置是
`~/.memory-home/personal/profile/exact.json`，与 Workspaces 平行而不是嵌套在某个
Workspace 中。

## 路径和写入检查

路径解析优先级：

1. `PMEM_FILE`：兼容覆盖，完整文件路径；
2. `PMEM_DIR`：兼容覆盖，目录内文件名固定为 `store.json`；
3. `${MEMORY_HOME:-~/.memory-home}/personal/profile/exact.json`。

`MEMORY_HOME` 是新安装推荐使用的统一根目录变量。旧
`~/.personal-memory/store.json` 可通过 `scripts/home.py migration-plan` 和显式
`migrate` 只复制迁移，原文件不会删除。

`PMEM_PROJECT_DIR` 已弃用并被忽略。`doctor` 显示的路径位于临时目录、远程临时
会话无法访问宿主机目录，或确切父目录不可写时，必须停止；不要把档案改存到当前
项目。每次成功覆盖会在同目录保留上一版文件的 `.bak`。

## 数据类型

- `single`：一个 key 对应一个完整原文，例如邮箱、学号、地址、电话。
- `entries`：一个 key 下的有序结构化记录，例如多段实习、获奖或项目经历。

不同版本、组织、账号或场景的标识符必须使用不歧义的 key；不能让一个值静默覆盖
另一个范围的值。

## 少量明确事实

用户一次提供 1–3 个明确事实时，不要在写入前逐项提问：

1. 原样提取 key 和 value。
2. 用 `set` 保存单值，或用 `add` 保存结构化条目。
3. 立即用 `get` 读回并逐字比较。
4. 简要列出已经保存的项目；若任一值不同，明确报告校验失败。

只有内容无法判断、存在冲突候选，或覆盖意图不明确时才先问。

## 大量信息

以下任一情况先给 checklist，不写入：

- 4 个及以上独立事实；
- 多条结构化经历；
- 从任何文件导入个人信息。

示例：

```markdown
请核对准备保存的信息：

- [ ] 姓名：……
- [ ] 学号：……
- [ ] 实习经历 1
  - 公司：……
  - 岗位：……
  - 时间：……
```

对缺失、冲突、排版断行或提取不确定的字段标记 `待确认`，不要猜。用户确认整个
checklist 后批量写入并逐项读回。用户明确说“无需核对，直接保存”时可以跳过确认，
但仍需读回。

## 从文件导入

1. 使用当前 Agent 环境已有的合适能力读取文件；不能可靠读取时如实说明。
2. 只整理用户要求保存的个人事实，不默认保存全文。
3. 保留原始拼写、大小写、标点和数字；不要静默修正疑似错字。
4. 能可靠取得页码、工作表或段落位置时，可作为 checklist 的核对依据，但默认不写入
   记忆值。
5. checklist 确认后再使用 `set` / `add`，并逐项 `get`。

## 场景召回

不仅在用户问“你记得我的……吗”时召回。任务确实需要用户本人的事实时，也应主动
使用，例如：

- 自我介绍、个人简介、个人陈述、简历或个人主页；
- 求职、入学、奖学金、签证、报名和申请材料；
- 官网、网页、表单、账户或报名页面中的个人资料。

若任务只是通用模板、表单代码或示例人物，不读取个人档案。

召回顺序：

1. 判断本次所需字段；明确时 `search`，范围较广时先 `list` 看 key 概览。
2. 只对需要的 key 使用 `get`；结构化条目可用 `--index` 和 `--field`。
3. 姓名、号码、日期、机构、岗位和奖项等事实逐字使用。叙述性文字可适配场景，但
   不得改变事实。
4. 缺少字段时只询问缺失项。输入与档案冲突时提醒用户选择。
5. 召回是只读操作；除非用户明确要求修改，否则不写回新内容。

## 隐私边界

存储文件是本机明文 JSON，不是加密保险库。不要保存密码、验证码、访问令牌、Cookie、
私钥或助记词。`list`、日志和无关回复不应展示完整敏感值。
